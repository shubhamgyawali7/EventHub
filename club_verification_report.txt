3. CLUB REGISTRATION & VERIFICATION FLOW
-----------------------------------------------------------
1. User Action: A user fills out the Club Registration Form on the frontend and submits it.
2. Form Submission: Sends `POST` data to `submitClubRegistration` on the backend.
3. Pending Phase: `clubService.applyForClub` creates a new `RegisterClub` document in the database with `status: "Pending"` and `isVerified: false`. It also attaches the `club` ID to the User's document.
4. Admin Dashboard: An Admin visits the Manage Clubs page. The frontend calls `getPendingClubs` which retrieves all clubs with the "Pending" status.
5. Admin Approval: Admin clicks the "Approve" button, firing off a `PUT /api/admin/clubs/approve/:id` request.
6. DB Update: The backend changes the `RegisterClub` document's status to `"Approved"` and `isVerified: true`. It also upgrades the User by adding `"Club"` to their `roles` array.
7. Email Fired: The HTML welcome email is sent to the club's contact email.

4. REQUIRED IMPROVEMENTS & FIXES (DO THIS BEFORE DEPLOYMENT)
-----------------------------------------------------------
[CRITICAL] Hardcoded Localhost URL in your Email Template:
In `server/src/utils/emailService.js` on Line 34, you have a hardcoded URL:
  <a href="http://localhost:5173/profile" ...>
Since your project is deployed to Vercel, users clicking "Access Your Dashboard" in their email will go to localhost (which won't work).
Fix: Change it to use your .env variable like this:
  <a href="${process.env.FRONTEND_URL}/profile" ...>

[Suggestion] Error Handling on Email Failure:
In `clubService.js` around line 49, you do `await sendVerificationEmail(club.email, club.name);`. If the email fails to send, your `emailService.js` simply returns `false` and `console.error`s the error. The admin will still see "Club approved successfully" even if the email failed. This is fine to prevent blocking the actual database approval, but you might want to return a flag to the frontend letting the admin know the approval worked but the email failed.

[Deployment Suggestion] Render Cold Starts:
Because you are using Render, the backend goes to sleep after inactivity. When an admin clicks "Approve", the backend might take 30-50 seconds to wake up and send the email. Ensure your frontend has a loading spinner during the approval state so the Admin knows it's working.
